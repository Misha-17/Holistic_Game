BEACON BAY - CORE AZURE DEDICATED SERVER
Updated: 2026-10-07. Applies to the current department-based codebase.

DEPLOYMENT FILES
Copy BOTH files from build/server/ to the same directory on the Azure VM:
  BeaconBay.x86_64
  BeaconBay.pck
These are the exported Godot 4.7.2 Linux x86_64 release files.
No editor, source tree, desktop environment or audio setup is needed to launch
this build in headless mode. Azure deployment itself has not been performed.

AZURE LAUNCH (from the directory containing both files)
  chmod +x BeaconBay.x86_64
  ./BeaconBay.x86_64 --headless --server

In a second terminal, check the listening socket:
  ss -lunp | grep ':24680'

Allow inbound UDP 24680 in the Azure network security group and VM firewall.
The owner previously reported Azure UDP access configured; this was not verified
remotely. No Azure address or credentials were supplied. No VM changes were made.

CLIENTS
Use normal desktop clients built from this same updated source version.
Open the existing cooperative lobby, enter the Azure VM public IP, and Join.
A bare IP or IP:24680 is supported by the current client.
Do not select Host when connecting to Azure.
For source clients, the existing --join=ADDRESS playtest argument also works.

One to four human players are supported. Server peer 1 occupies no human seat.
First-free seats are assigned in connection order. With four connected humans:
  Player 1: Fire
  Player 2: Medical
  Player 3: Engineering
  Player 4: Police
This is the CURRENT department-based game, not the old Dispatcher/RM/FC/SM game.
The existing department splits redistribute departments when someone leaves.

SESSION BEHAVIOR
There is no automatic start at any player count. The first connected player
clicks START SHIFT TOGETHER in the existing lobby to begin Shift 1 with 1-4
players. If that player leaves before starting, the earliest remaining player
can start. This uses roster arrival order, not departments or seat numbers.
After start, disconnect/reconnect does not reset the simulation.
After Shift 1 ends, the server stays on results. Restart the process for the
next session. No automatic next shift, remote admin or extra lobby was added.
Normal desktop Host still occupies seat 0 and accepts three remote clients.

CORE IMPLEMENTATION
scripts/network_session.gd:
- host(server_only=false) retains desktop default; true opens four remote slots,
  empty human roster, local role -1, same UDP 24680 ENet authority.
- Existing compressed snapshots, events and command validation retained.
- Dedicated mode skips UPnP and disables unused client-to-client relay.
- Dedicated disconnect roster updates and announcements are deferred until
  ENet finishes disconnect polling. Desktop roster behavior is retained.
- Roster RPC carries a dedicated flag and validates server-only membership.
- Broadcasts use actual remote peer count, so one remote player gets updates.
- close() restores normal relay behavior for later desktop sessions.

scripts/main.gd:
- Detects --server in engine or user arguments before presentation setup.
- Reuses common NetworkSession creation and existing command/simulation paths.
- Dedicated startup creates no map, HUD, tutorial or audio nodes; ResearchLogger
  remains disabled. No local profile loading or campaign saving.
- Manual start_shift uses the existing command RPC; the server validates the
  earliest connected player, lobby state and one-time start before _begin_shift(0).
- Existing simulation tick and 0.12-second broadcast threshold retained.
- Dedicated results do not grant local campaign rewards or start another shift.
- Console startup, assignment, departure, shift-start/end and bind-failure text.
- Guest lobby reuses the existing Start button for the session starter.

export_presets.cfg:
- Added Linux Server, x86_64, separate PCK, build/server/BeaconBay.x86_64.
- Existing Windows Desktop export preset unchanged.
- Normal export assets retained; --headless --server activates runtime mode.

No parent _exit_tree() network.close() call was added: child nodes have already
left the SceneTree by then. Normal engine peer disposal handles process shutdown.
